# コミット & push

main ブランチに直接コミットして push する運用(PR フローは使っていない)。以下を順に行う。

## 1. 変更内容の確認

```bash
git status --short
git diff --stat
```

- 未追跡ファイル(`??`)も含め、今回の作業で作ったファイルか確認する。作業と無関係な変更・`.env*` などの秘密情報が混ざっていたら、コミットに含めずユーザーに確認する
- 無関係な目的の変更が混ざっていたら、目的ごとにコミットを分ける(1コミット1目的)

## 2. 品質チェック(/preflight と同じ)

```bash
npm run lint
npm run build
```

- 失敗したら修正して再実行する。失敗したままコミット・push しない

## 3. コミット

- メッセージは `/commit-msg` の流儀に従う(日本語・1行・接頭辞なし。例:「成績に通算記録室タブを追加」)
- ファイルは `git add -A` ではなく、対象ファイルを明示して add する
- `git diff --staged --stat` で、ステージ内容とメッセージが一致しているか確認する
- メッセージの末尾には、会話で指定された Co-Authored-By 行を付ける

## 4. push

```bash
git push
git log --oneline -3
```

- push が拒否された(リモートが先行している)ときは、勝手に force push しない。`git pull --rebase` で取り込めるか確認し、コンフリクトがあればユーザーに相談する

## 5. 報告

- 作成したコミット(ハッシュとメッセージ)と push 先を短く伝える
- lint・build の結果も一言添える
